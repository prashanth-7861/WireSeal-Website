Installation

Get WireSeal running on your system in minutes.

System requirements

  • Ubuntu 20.04+, Debian 10+, Fedora 35+, RHEL 9+, Arch Linux
  • Raspberry Pi OS (Debian-based)
  • Root or sudo access

Run

# Fedora/RHEL

sudo pacman -S webkit2gtk

Install Script — One-liner install with automatic dependencies

Install

curl -fsSL https://github.com/prashanth-7861/WireSeal/releases/latest/download/wireseal-linux.sh -o wireseal-linux.sh
chmod +x wireseal-linux.sh
sudo ./wireseal-linux.sh

The install script automatically installs WireGuard, Python, and configures the firewall.

Usage (CLI / Script)

Initialize VPN server

sudo wireseal init --subnet 10.0.0.1/24 --port 51820

Creates vault, generates keys, configures firewall

Forward the WireGuard port on your router Required for remote access

To reach your home from outside, add one port-forward rule in your router's admin page. WireSeal configures the server's own firewall + NAT automatically, but it can't change your router for you:

  • Protocol: UDP — WireGuard is UDP, so a TCP rule will not work
  • External / WAN port: the port you picked at init — default 51820
  • Forward to: your server's LAN IP (e.g. 192.168.1.100) on the same port

Changed --port? Forward that port instead. If your ISP rotates your public IP, run wireseal duckdns <name> so clients always find you. Automatic UPnP/NAT-PMP forwarding is on the roadmap.

Open dashboard

sudo wireseal serve

Opens web dashboard at http://localhost:8080

Add client

sudo wireseal add-client alice

Adds a new client named alice and generates a QR code. Scan the QR with the WireSeal mobile app to connect instantly.

List clients

sudo wireseal list-clients

Show all registered clients with their public keys, IP assignments, and connection status. Useful for auditing who has access.

Show client QR

sudo wireseal show-qr alice

Re-display the QR code for an existing client. Useful if the original QR was lost before the mobile app scanned it.

Export client config

sudo wireseal export alice --output /tmp/alice.conf

Save the client's WireGuard configuration to a file. Share this with the client for manual setup if QR scanning isn't available.

Remove client

sudo wireseal remove-client alice

Revoke a client's access immediately. The client's key is removed from the server — they will lose connectivity on their next handshake.

View status

sudo wireseal status

Display live connection status: connected peers, transfer statistics (bytes sent/received), and tunnel uptime for each client.

Rotate client keys

sudo wireseal rotate-keys alice

Generate a new key pair for a client and invalidate the old one. The client will need to re-authenticate with the updated configuration.

Rotate server keys

sudo wireseal rotate-server-keys

Regenerate the server's private key and redistribute updated configs to all clients. All clients must reconnect after this operation.

Update endpoint (DuckDNS)

sudo wireseal update-dns

Update the dynamic DNS record with your current public IP. Run this periodically or set up a cron job if your ISP assigns dynamic IPs.

Backup vault

sudo wireseal backup-vault /path/to/backup

Create an encrypted backup of your entire WireSeal vault — all keys, client configs, and settings. Store the backup in a safe, offline location.

Lock vault

sudo wireseal lock

Lock the vault and stop all VPN traffic. The server remains running but no data passes through until the vault is unlocked with your passphrase.

Change passphrase

sudo wireseal change-passphrase

Update your vault passphrase. You will be prompted for the current passphrase first, then asked to enter and confirm the new one.

View audit log

sudo wireseal audit-log

Display the server's audit trail: client connections, disconnections, key rotations, config changes, and admin actions with timestamps.

Terminate VPN

sudo wireseal terminate

Gracefully bring down the WireGuard tunnel, remove the network interface, and disconnect all clients. The vault and configuration are preserved.

Fresh start

sudo wireseal fresh-start

Wipe all WireSeal data — vault, keys, client configs, and logs — then re-initialize from scratch. Use this only if you want a completely clean setup.

Troubleshooting

Permission denied

WireSeal requires root privileges to create network interfaces, modify firewall rules, and manage the VPN tunnel. If you see Permission denied, prefix your command with sudo.

For convenience, run sudo -i once to open a root shell, then execute commands without re-typing sudo each time.

WireGuard not found

WireSeal depends on the wireguard-tools package for kernel interface management. Most distributions ship it in their default repos.

Install it with: sudo apt install wireguard-tools (Debian/Ubuntu), sudo dnf install wireguard-tools (Fedora), or sudo pacman -S wireguard-tools (Arch).

Port in use

Another service may already be using UDP port 51820. You can specify a different port during initialization.

Use: sudo wireseal init --port 51821 to pick an alternative port, then update your router's port-forward rule to match.

Firewall blocked

WireSeal automatically configures ufw (Ubuntu/Debian) or firewalld (Fedora/RHEL) to allow WireGuard traffic on the configured port during init.

If you're using a custom firewall, ensure UDP traffic is allowed on your WireGuard port. No manual iptables rules are needed in most cases.

Troubleshooting

Permission denied

WireSeal requires Administrator privileges to create network adapters and configure firewall rules. Right-click your terminal (PowerShell or CMD) and select Run as Administrator.

Commands that modify system network settings will fail silently without elevated privileges.

WireGuard not found

WireSeal uses the official WireGuard for Windows kernel driver. The install script downloads and installs it automatically if missing.

For manual install, download from wireguard.com/install — the tunnel adapter is required for VPN operation.

Port in use

Another application may already be listening on UDP port 51820. You can change the port during initialization.

Run: wireseal init --port 51821 to use an alternative port, then update your router's port-forward rule accordingly.

Firewall blocked

WireSeal automatically creates a Windows Firewall rule to allow inbound UDP traffic on the configured WireGuard port during initialization.

If you're using a third-party firewall suite, verify that UDP traffic is permitted on your WireGuard port. Check Windows Defender Firewall with Advanced Security for any blocked connections.
